# Запуск SmartHub: Vercel + домен smarthub-kz.com

Код готов и проверен локально. Ниже — шаги, которые **выполняете вы**: они требуют
входа в ваши аккаунты, а я в чужие аккаунты не логинюсь и пароли не ввожу.

Времени: ~20 минут.

---

## 0. Сначала смените пароль hoster.kz

Он был отправлен в переписку открытым текстом, значит считается скомпрометированным.
Смените его и включите двухфакторную аутентификацию. Почта, привязанная к аккаунту,
тоже под угрозой — через неё восстанавливается доступ к домену.

---

## 1. Установить Vercel CLI и войти

```bash
npm i -g vercel
vercel login
```

## 2. Первый деплой

Из папки проекта:

```bash
vercel
```

Отвечаете: `Set up and deploy` → **yes**, scope — ваш аккаунт, link to existing — **no**,
имя проекта — `smarthub`, каталог — `./`, менять настройки — **no**.

Получите превью-ссылку вида `smarthub-xxxx.vercel.app`. Заявки на ней ещё не сохраняются —
это следующий шаг.

## 3. Подключить базу данных PostgreSQL

Без неё заявки живут в памяти и пропадают при каждом перезапуске.

**Вариант А — база от Vercel (быстрее всего):**
Vercel → проект → **Storage** → **Create Database** → **Postgres** → регион Frankfurt → **Create**
→ **Connect to Project**. Переменная `DATABASE_URL` пропишется сама.

**Вариант Б — свой сервер PostgreSQL:**
добавьте переменную вручную на шаге 4:

```
DATABASE_URL=postgresql://пользователь:пароль@хост:5432/база
```

Если у сервера самоподписанный сертификат, добавьте ещё `PGSSL_NO_VERIFY=1`.

Таблицу создавать руками не нужно — при первом обращении выполняется:

```sql
CREATE TABLE IF NOT EXISTS leads (
  id TEXT PRIMARY KEY,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  type TEXT NOT NULL, name TEXT NOT NULL, phone TEXT NOT NULL,
  email TEXT, program TEXT, message TEXT, lang TEXT, page TEXT, ua TEXT
);
CREATE INDEX IF NOT EXISTS leads_created_at_idx ON leads (created_at DESC);
```

## 4. Задать пароль администратора

Vercel → Settings → **Environment Variables** → добавить для всех сред:

| Переменная | Значение |
|---|---|
| `ADMIN_PASSWORD` | длинный пароль для входа в `/admin` |
| `ADMIN_SECRET` | любая случайная строка от 32 символов |

`ADMIN_SECRET` подписывает cookie сессии. Смена этой строки разлогинивает всех.

## 5. Боевой деплой

```bash
vercel --prod
```

## 6. Домен

**В Vercel:** Settings → Domains → добавить `smarthub-kz.com` и `www.smarthub-kz.com`.
Vercel покажет, какие записи нужны.

**В hoster.kz:** личный кабинет → домен `smarthub-kz.com` → DNS-записи:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | `76.76.21.21` |
| CNAME | `www` | `cname.vercel-dns.com` |

Точные значения берите из панели Vercel — если они там отличаются, верны они.
DNS расходится от 15 минут до нескольких часов. HTTPS Vercel выпустит сам.

## Что где лежит

| Путь | Назначение |
|---|---|
| `index.html` | лендинг |
| `admin.html` | админка, доступна по `/admin` |
| `api/lead.js` | приём заявок с форм (публичный) |
| `api/leads.js` | выдача заявок в админку (только с сессией) |
| `api/login.js` | вход, выход, проверка сессии |
| `lib/store.js` | доступ к PostgreSQL и подпись сессии |
| `assets/` | логотипы, фото, графика |

## Как работает админка

Открываете `/admin`, вводите `ADMIN_PASSWORD`. Список сам обновляется раз в 7 секунд,
новые заявки подсвечиваются. Есть фильтры, поиск и выгрузка в CSV с BOM — Excel
откроет кириллицу правильно. Во вкладке в фоне опрос останавливается, чтобы не жечь лимиты.

## Что уже сделано для защиты

- Пароль только в переменной окружения, в коде и репозитории его нет
- Сессия — подписанная HMAC cookie: HttpOnly, SameSite=Strict, Secure на проде, 12 часов
- Сравнение пароля постоянное по времени
- Не более 8 попыток входа с адреса, дальше 15 минут блокировки
- Скрытое поле-ловушка в обеих формах: боты его заполняют, заявка тихо отбрасывается
- Ограничение размера тела запроса, обрезка полей, вычистка управляющих символов
- Админка закрыта от индексации (`noindex` + `X-Robots-Tag`)

  законодательству РК нужен чекбокс согласия и страница политики. Юридическая часть —
  не моя зона, но место под чекбокс подготовлю, если скажете.
